Four tools, one question: is DNS doing its job?

Each test sends the same query, with the same timeout and the same number of attempts, to both resolvers so the results can be compared fairly.

DNS resolver comparison

See both resolvers side by side: returned addresses, response codes, record consistency and which one answered faster in this test.

Real-time latency analysis

Every attempt is timed with a high-resolution clock. Median latency uses successful answers only, so a timeout never skews the figure.

DNS error classification

NOERROR with records, NOERROR without the requested record, NXDOMAIN, SERVFAIL, REFUSED and timeouts are each identified separately.

Intelligent diagnostics

Fixed, auditable rules explain each outcome and suggest follow-up checks, without claiming a root cause the evidence cannot support.

How a DNSGuard test works

The same flow described in the project synopsis, from input to stored report.

Choose the query

Enter a domain, pick an A (IPv4) or AAAA (IPv6) record, the resolvers, the number of attempts and a timeout.

Send real queries

dnspython builds a DNS message with recursion desired and sends it over UDP port 53, retrying over TCP if the answer is truncated.

Classify and measure

Each response code is classified, the CNAME chain is followed, and latency, success count and failure rate are calculated.

Explain and store

Rule-based diagnostics explain the outcome, the resolvers are compared, and the full report is saved to SQLite.
